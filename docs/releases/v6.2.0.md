# v6.2.0 更新说明

> 从 v6.1.0（versionCode 100）之后累计 6 个提交，versionCode 递增 1。
> 一句话：**首页入口顺序这次真的生效了；同时把仓库里"写了没接上"和"测了但测的是死路"两类问题一次清干净。**

## 用户能看到的

- **设置 → 常用入口顺序**：可以把「定时」「播放器」「演示」「权限」四块入口按需排到前面。这套机制此前只有对话框和存储，没有任何消费者，也没有入口——选了没反应。现在实现真的按存储的顺序重排首页，且只在这四块之间移动，黑幕主卡、最近听过、节能统计原地不动；点「恢复默认顺序」可回退。
- **首页「播放来源」卡片改为按状态显示**：有可读的播放会话时出现，报来源与它支持什么（暂停/跳转/切集）；没有会话时不再占位。它原来那句「请选择播放器」服务的是 v5.0.1 已撤掉的播放器选择流程，留着就是指向不存在界面的死入口，所以这次改的是内容语义而不是简单显示出来。卡片不再可点（它的监听器本来就是空的）。
- 上一版（v6.1.0）的三处通知使用权入口照常有效：首页第四行、定时弹窗内「去授权」、设置页「诊断与自检」。

## 内部质量

- **接上一个从没跑过的检查**：`SessionUiDeviceChecks` 在仓库里没有任何调用点，且两半断言都对着 v5.0.1 之前的实现。现在它守的是通知栏正文与桌面小组件真正共用的文案（8 种语言逐一核对），并挂成可重放的检查项 `session_text`。
- **把压在死路径上的用例搬到活路径**：备份导入的 7 条用例原先测的是没人调用的 `filterImportSessions`，而恢复真正用的 `validBackupSessions` **一条用例都没有**；转过去并补齐判据后 7→14 条。同理把 `StreaksTest` 的三条转守 `epochDayOf`，把对话框矩阵里的 presets 用例转守生产真会走的那条。
- **删掉 12 个全仓零引用的死函数**（含被更强实现取代的、和 v5.0.1 回退留下的 `= Unit` 空壳），以及二阶浮现的一个。
- **清掉 13 条死 import 与 63 条未使用资源**：lint 警告从 77 降到 14，未使用资源归零。

## 验收

- 单测 38 类 247 例 0 失败。
- lint 错误 0、警告 14（v6.1.0 时为 77）。
- i18n 各语言包同步。
- 设备检查五组全通过：`correctionOnly`（守首页层级不被场景堆叠顶掉）、`incrementDialogs`（96 个对话框 × 8 语言 × 2 主题）、默认全流程、`session_text`、`app_choices`。
- 入口顺序改动在 api35 上实拍验证：提升「演示」后 "Try a test sound" 实际移到 Sleep timer 之上，恢复默认后回到原位。

## 本版未验与已知边界

1. **真机未覆盖**：本版全部证据来自模拟器 api35。上一版遗留的那条——「新播放器出现 → 定时弹窗单选变亮」——仍需真机开播放器后台播放补验。
2. **入口顺序只影响这四块入口的先后**，不改变它们各自的内容与权限；非参与模块（黑幕主卡、最近听过、节能统计）不参与排序，这是有意的，避免"排个序把主操作挪走"。
3. **播放来源卡片没有点击动作**。若要加，最诚实的候选是"回到来源 App"，本版未做。
4. 仍保留 8 个"逻辑被测试锁着、生产从不走"的函数未删（如 `isDemoAudioPlaying` 是测试探针），它们的去留是产品判断，不是死代码问题。
