# 下一次大版本计划：接着听与随手标记

日期：2026-10-17。状态：用户已授权按A→F开发并UAT后交付。面向所有播放平台，不设置白名单；三款App仅为测试样本。

本计划基于用户确认的方向编制，取代下一版对旧完整记录库的执行安排；旧方案保持暂停，不恢复搜索、合集和独立收藏页。建议版本定位v6.0，版本号在发布准备时确定。后续开发默认由当前Agent连续执行，涉及共享数据与播放状态的任务串行推进。

## 1. 目标与版本价值

让用户今晚听过的内容，明天能够找到；让用户听到值得记住的地方时，留下可回顾的标记。继续辅助其他视频App，原App负责内容与播放。

成功标准：用户无需理解媒体会话和包名，能够完成“听一段→结束→在本应用找到记录→执行准确命名的返回动作”；没有内容信息时，界面也不误导、不展示旧标题、不制造假进度。

本轮只编制方案，不修改产品代码、不安装候选、不发布。交互草图确认后才进入实现；本文是版本计划，不代替开发前对接口和恢复方案的最终设计。

## 2. 范围与优先级

| 优先级 | 工作 | 本版交付 |

## 3. 五条用户路径

### 3.1 普通听剧后找回

1. 用户在原App播放，点击现有悬浮球进入黑幕。
2. 首次升级通过一次短说明告知本地记录和保留规则，提供关闭自动记录选项；后续无逐次弹窗。
3. 自动记录仅保存来源与可靠内容信息。只有App名、没有可靠标题时，不在“最近听过”制造具体内容卡片，也不弹报错；原有时长统计照常工作。
4. 返回本应用：首页原启动按钮保持主位，新增一行“最近听过”入口，最多一条最近可靠记录的摘要，无记录时不占大卡片。
5. 进入列表或详情，按实际能力打开原内容、打开网页或打开来源App。自动记录不等于已经拿到内容链接。

### 3.2 当前App不提供内容信息

1. 在原App通过系统分享选择息屏听剧；只有复制链接的App，用户复制后进入本应用点击“粘贴链接”。
2. 预览显示收到的文字、链接和目标行为；标题缺失允许补充。
3. 用户点击“保存”才写库；取消、返回、旋转重建均不能误保存。
4. 后续播放期间不能仅凭相同App或相同标题，将这条链接自动挂到未知内容。无法确认是同一内容时保持独立，允许用户在详情中明确关联。

### 3.3 随手标记

1. 设置新增“黑幕显示标记入口”，默认关闭，与睡前定时显示独立。
2. 开启后，黑幕仍需先轻点唤醒面板，才显示“记住这里”；锁定黑幕不接收标记操作，悬浮球单击语义不变。
3. 点击保存当时快照，反馈“已标记”，不弹键盘、不切换播放器、不暂停声音。提交期间按钮禁用，完成后允许再次标记。
4. 有可靠内容及进度时保存时间点；只有可靠标题时保存内容标记；连标题也没有时，仅用户主动操作可建立“未识别内容”的标记，注明App和时间，不能伪装成已知剧集。
5. 记录详情可补短备注、删除单条标记。黑幕不承担整理和输入任务。

### 3.4 睡前回听

1. 用户设置睡前定时，沿用现有受理与暂停判断。
2. 仅在服务确认成功受理后，保存“设置定时时的位置”；受理失败、过期请求不建立成功记录。
3. 定时结束，保存可确认的结束状态；不把请求暂停当暂停成功。
4. 次日详情显示“设置定时时的位置”和可用的最近位置，动作遵守找回能力。重新设置定时可新增起点，取消定时不删除已形成的历史起点，标注已取消。
5. 不新增自动套用定时，不默认开启黑幕定时显示，不推送“昨晚听完”等无法证明的结论。

### 3.5 管理数据

记录页→管理与清理→保留期限/预览将删除的数量→确认。单条记录可“保留这条”、取消保留、删除。清空全部需单独确认。删除记录不改变累计时长、精灵成长和成就。

## 4. 页面与动作约定

保留首页、统计、设置三个底部页签，不增加控制台。新增页面限于最近列表、记录详情、保存预览、管理清理；先提供四页草图及首页入口、黑幕入口示意，再做视觉确认。

| 页面 | 首要内容 | 操作 |
| --- | --- | --- |
| 最近听过 | 时间倒序、App名称和图标、可靠标题、可用位置 | 点进详情；保存链接入口 |
| 详情 | 原内容、标记、备注、回听起点 | 按能力返回、保留、删除、明确关联链接 |
| 保存预览 | 分享或粘贴收到的信息与有效链接 | 编辑显示标题、保存、取消 |
| 管理清理 | 保留期、普通与保留记录数量、清理预览 | 按时间清理、清空全部 |

动作名必须准确：有链接叫“打开原内容”；明确经网页返回时提示可能需要点击打开App；只有来源App叫“打开来源App”；没有可靠返回目标时显示“暂不能定位原内容”，允许补链接。仅在同内容和位置恢复均验证成立的适配路径上提供定位动作。冷启动后不能凭旧MediaSession token跳进度，更不能对当前其他内容seek。

不展示包名、底层异常或协议错误；可恢复错误使用“链接暂时打不开，可复制链接后重试”等普通语言。没有进度不显示进度条。

## 5. 数据及可信性设计约束

新增SQLite内容库，和SessionLog/HistoryStore时长统计分开。建议模型分为内容条目、听剧片段、标记三个实体；同内容多次听的片段可归到同一条目，位置不全时仍保留片段上下文。

- 条目：稳定内部ID、来源App、可空标题/链接/外部身份、信息来源、主动保存/保留标志、创建和最近活动时间。
- 片段：条目ID、黑幕起止、可空位置和时长、关联定时受理状态；不声称整个片段声音连续。
- 标记：条目/片段ID、创建时间、当时标题和来源快照、可空位置、备注、类型（手动/定时起点）。
- 所有位置附采样时间、来源及可信状态；未知用null，不用0冒充。未知总时长不得用于计算听完比例。
- 可靠内容身份变化则分段；只改标题不证明是新内容，重复标题不证明是同内容。来自旧App的异步回调不得写进新App片段。
- 主动分享URL精确匹配或经验证的同源稳定身份才允许自动去重。短链不自行联网展开；不按标题模糊合并。
- 内容与分享无法自动关联时，用户必须明确选择一条记录关联；不弹出自动匹配成功。
- 不新增INTERNET权限，不新增第三方SDK，沿用Kotlin和Android原生界面。截图、原始通知、媒体token、原始音视频不入库。
- 自动内容记录可关闭，默认开启但首次说明；关闭后停止新增自动片段，已有数据可清理，主动保存与主动标记仍由用户决定。
- 旧统计时段不批量迁成内容条目，不伪造历史视频。

## 6. 保留、清理与备份

- 普通自动记录默认90天，可选30/180天/永久；以最后片段结束时间，无结束时间取创建时间判断到期，到期边界包含截止时刻。
- 主动保存链接、手动标记、非空用户备注或“保留这条”均受保护。系统自动生成的定时起点不自动变成永久保护，以免每天定时使清理失效。
- 最后一项保护移除后提示恢复期限管理，不在点击瞬间后台删除。
- 首次清理及备份恢复后的首次清理提供预览；后续普通到期清理在打开记录页或写入后异步检查，每24小时最多一次，无新增常驻后台任务。
- 清理提交时重新检查保护状态；预览后新增标记/备注的记录跳过删除，显示实际结果。条目、片段、标记删除用同一事务。
- 备份由当前v4扩展新版本，保留v1–v4读取路径；旧备份没有内容库时保留本机内容库，并在恢复预览解释。
- 新版备份包含内容库时，采用恢复前预览与整库替换语义；先制作独立数据库快照，再恢复偏好与统计，任一步失败全部回滚。失败启动恢复也必须覆盖新库。
- 不将整个数据库塞进现有2MiB JSON恢复快照，也不只提高限制掩盖体积问题。最终快照文件、journal和锁顺序在实现设计中明确，开发前审查。
- 备份包含标题、链接和备注，用户主动导出时告知；导出文件的保存期由用户管理，不随本机清理同步删除。

## 8. UAT矩阵与发布条件

| 场景 | 判定标准 |
| --- | --- |
| B站普通视频 | 记录与当前内容一致；普通分享实际返回同视频；带进度分享单独验证 |
| 爱奇艺正文、换集 | 不沿用旧B站标题；信息缺失有明确降级；粘贴链接回同集和位置恢复分开记 |
| 抖音短视频、连续切换 | 标记不落到上一条；找回失败如实提示；不能用来源App识别代替内容识别 |
| 多App来回切换 | 标题、位置、定时起点不串App；失效旧会话不控制新播放 |
| 取消分享与进程中断 | 不误保存、不重复、恢复后无半条数据 |
| 黑幕误触 | 默认无定时/标记入口；开启后需唤醒才可操作；自动重锁有效 |
| 既有睡前定时 | 一分钟暂停、只撤幕、取消/延长、暂停未确认仍保持既有正确行为 |
| 老版本升级与恢复 | 原设置、累计统计和成长保持；失败回滚可用 |
| 期限与保护 | 精确边界、标记保护、去保护、清理竞态及恢复后预览全部通过 |
| 无权限、未安装、离线 | 保存本机记录可用；缺失权限说明清楚；链接返回失败不崩溃 |
| 深色/长文/大字/横屏 | 页面可读、按钮不遮挡；字体旋转矩阵只在模拟器执行 |

性能目标：模拟1万条条目、2万条标记，列表分页50条；OPPO测试机列表从查询到可交互的目标≤500ms。数据库和清理不在主线程；不自动删数据满足性能。若不达标先优化分页/索引，并保留实测结果。

> 2026-10-20 调整：最近听过首屏由 50 条改为 10 条（`ListeningStore.PAGE_SIZE`）；500 ms 仍只对 OPPO 真机，模拟器只记录同口径基线。改后模拟器 host GPU 热启中位 553–575 ms（两轮，单次 547–658 ms），不代表真机达标。

每个真机用例先读取旋转设置，启动息屏听剧和服务、确认悬浮球，再在原App实际播放并开黑幕；完成后读回旋转，不能开启自动旋转当清理。系统广播和模拟媒体会话不能替代真实耳机/来电/声音验收；用户听感确认与自动化证据分别记录。本次无新精确耗电实验。

发布底线：P0全部通过；标记与返回不污染内容；无数据丢失/恢复阻塞；已支持路径有真实点击证据；未支持App明确降级。测试数量不作为跨App兼容率。

## 9. 后续路线（本轮不实施）
