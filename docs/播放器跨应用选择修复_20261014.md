# 播放器跨应用选择修复

用户实报：切换其他视频软件后，选择播放器里依旧只有哔哩哔哩。

## 复现与根因

OPPO PME110/API36：真实爱奇艺进程有音频播放，系统媒体会话为inactive/STATE_NONE，活跃媒体控制列表里仍有旧B站PAUSED会话。原UI把 `getActiveSessions()` 的可控制会话当作完整播放器目录，又把“没有token”当作“没有明确选择”。这会遗漏没有发布有效会话的应用，并使旧来源在界面中继续占位。

本轮不把声明了PAUSE标志、已安装或有声音等同于可可靠控制，也不把未发布会话解释成缺通知权限。爱奇艺当前具体播放链路不能宣称已支持暂停/片尾。

## 修复契约

- 目录合并已安装视频应用、视频文件处理应用和有效媒体会话，使用已有MAIN/LAUNCHER可见性，不增加权限。展示真实应用名称、图标及当前会话能力；已暂停的B站明确标注。
- 明确选择的应用包名与具体媒体token分开。选择无会话应用时清除旧会话，查询和媒体键不能跨包回落。若之后同包提供有效会话，可绑定该包；既有具体token销毁仍要求重选。
- 无可控制会话时支持基础黑幕与固定时间返回，暂停/片尾不可用。首页、黑幕内与定时弹窗使用同一应用目录和选择约束。
- 请求携带所选包名。服务校验pkg/controller一致性，受理前不得改原定时或偏好；固定返回不再携带旧缓存B站token。既有已启动定时独立保持原target，不因用户选择另一应用而重绑。
- 常用定时按受理的应用包保存；UI迟到accepted回调不再次覆盖选择。

用户明确质疑“选择播放器”的产品意义，认为应默认面向当前播放内容。该纠偏合理：5.1.2只修复目录可选/目标隔离，手动固定选择仍不是最终目标。后续设计应默认自动跟随当前可靠可识别的播放源，手动指定退为歧义时次要入口；既有定时仍固定原target，不跨App误控。对于无有效MediaSession的爱奇艺，不能凭旧B站PAUSED会话假定当前播放器；需明确识别边界，不能将显示已安装名称等同于自动识别。尚未实现自动跟随的新设计。
