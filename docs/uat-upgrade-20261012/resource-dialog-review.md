## 布局问题与最小修复建议

1. **历史管理固定高度与横屏冲突（源码确定，设备表现待验）**。`HistoryManagement.kt:45` 将记录滚动区固定为 300dp，说明文字、日期选择、全部日期与导出三个按钮位于滚动区外，`setView(content)` 的父容器也不滚动。仅记录区域就接近 320dp 横屏窗口的全部高度，顶部控件、标题和关闭按钮仍需额外空间；大字体与长翻译进一步增加高度。最小修复：让整个自定义内容使用一个 ScrollView，取消内部记录区固定 300dp，让说明、筛选、导出和所有记录共同滚动，关闭按钮保留为系统对话框按钮。验收需验证最末条记录与导出/筛选按钮都可实际滚动到达。

2. **备份管理自定义内容没有滚动路径（源码确定，是否裁剪取决于设备测量）**。`BackupManagement.kt:17-37` 直接传入垂直 LinearLayout，包含自动备份 Switch、备份状态和两个操作；法语标签 `Sauvegarde automatique dans Téléchargements` 较长。横屏低高度配合 1.5–2.0 字体会增加换行高度，末尾“撤销恢复”可能超出可见区域。最小修复：用 ScrollView 包住 box，并将原始像素 padding 换成 dp。列表型历史/备份选择弹窗使用系统 `setItems`，已有列表滚动支持，不能与该自定义 box 混为一谈。

3. **首次成功引导的三个按钮有窄屏长文案拥挤风险（待设备确认）**。`FirstSuccessFlow.kt:11-23` 同时使用 positive、neutral、negative。德语按钮为 `10-Sekunden-Demo starten`、`Ergebnis prüfen`、`Abbrechen`；西班牙语、法语、俄语也较长。`AccessibilityUi.apply` 设置最小触控尺寸，没有为这些按钮提供文案换行或纵向布局。原生按钮栏是否自动堆叠取决于系统主题/API，应在 API 26/33/36、320dp与大字体下实际检查三按钮完整文字与可点击性。若出现挤压，最小修复为把“启动演示/检查结果”改为两个系统列表项，保留取消作为底部按钮。

4. **外观与入口顺序弹窗：未发现源码可确认的自定义固定高度缺陷**。`AppearanceSettings.kt:54-74` 使用原生 `setItems`/`setSingleChoiceItems`，条目少，具备系统列表测量与滚动机制。“恢复默认顺序”与取消共两个底部按钮，德语 `Standardreihenfolge` 仍应加入320dp大字体实机检查，但当前证据不足以认定其裁剪。

## 验收覆盖边界

`UpgradeDeviceChecks.renderMatrix()` 的 288 变体只渲染三个页面 XML 与三个 widget XML，未调用上述四个动态弹窗。它只能证明这些 XML 可以测量/绘制，不能证明动态弹窗的长文案、底部按钮、记录末项可达。`SupportDeviceChecks` 对首次成功确认只检查按钮非空和否定分支路由，没有更改字体或窗口方向，也没有覆盖首次启动的三个长按钮布局。

建议补充最小动态验收：历史管理、备份管理、首次引导、入口顺序各在德语/法语、320dp窄屏与640×320dp横屏、1.5/2.0字体检查，确认所有操作可见或可滚动到达。此报告没有声称这些配置已在设备上通过。
