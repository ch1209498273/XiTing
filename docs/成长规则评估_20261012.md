# 成长规则评估 · 2026-10-12

本次交付为全量升级方案 F09 的规则评估，不改变成长契约。推荐本轮保留待收容量 200、生成后 72 小时过期、主动收取与现有成长/成就门槛；未来有明确反馈后，再独立决定是否扩大容量或延长有效期。本文依据源码静态核对，不使用私人用户数据，不代表真实用户反馈、机型验证或 UAT 已通过。

## 现行规则与事实纠正

**200 是待收能量库存容量，不是每日上限。** `EnergyStore.MAX_PENDING` 限制所有未收取球的值之和；满仓后新增能量被截断或丢弃，收取腾出空间后，同一天仍可继续产生能量。没有“每天 200、次日重置”逻辑。（`app/src/main/java/com/lujinyu/xiting/EnergyStore.kt:39–42、60、95–103`）

**3 天是从每枚球生成起算的 72 小时，不是三个自然日。** 生成时记录 `expireAt = now + EXPIRE_MS`；调用 `pending()` 时过滤 `expireAt <= now` 的条目并回写，没有独立的到期后台任务。临期提示窗口为 12 小时。计时使用墙钟，手动调整系统时间可能改变有效期判断。（`EnergyStore.kt:58–59、80–91、101–103`）

待收能量与已收集成长值分别保存。主动收取单枚或全部有效球后，才累加到成长值；已收集成长值不受 3 天过期规则影响，累加采用整数饱和保护。（`EnergyStore.kt:54–55、77、108–140`）

能量来源不只有普通听剧分钟：黑幕会话按每满一分钟 1 点结算，零头跨会话累积；满足至少 5 分钟的会话还有 10% 概率稀有掉落，每日最多触发一次，其奖励按分钟计算且至少 15 点；每日分享奖励也进入同一待收库存。稀有掉落先于普通听剧能量入仓，满仓时两者都可能损失。分享/稀有奖励的每日去重标记不会因容量不足自动回滚。（`app/src/main/java/com/lujinyu/xiting/BlackOverlay.kt:503–531`；`app/src/main/java/com/lujinyu/xiting/PosterFlow.kt:285–300`）

例如已有 190 点待收，又结算 30 点时，只增加 10 点，其余 20 点不会排队补发；当天收取后可重新积累。已过期或满仓丢弃的能量没有可追溯的完整奖励流水，不能仅凭历史听剧时长准确补偿。

## 与历史、成就、皮肤和备份的关系

| 对象 | 实际关联 | 调整规则时的影响 |
|---|---|---|
| 听剧历史 | 有效会话由 `SessionLog.add()` 独立写入，`HistoryStore.record()` 累加总时长、次数、日期和月聚合 | 待收满仓或过期不删除已经记录的有效会话；不能把能量损失描述为听剧历史丢失 |
| 成长形态 | 使用已收集成长值，五阶门槛为 0 / 30 / 300 / 1500 / 6000 | 扩容或延长有效期可能减少损失、加快未来进阶；不会自动补回旧损失 |
| 四项成就 | 单次 1 小时、历史最长连续 7 天、100 次会话、成长满级 | 前三项直接依赖历史；满级成就通过已收集成长值间接受影响。已解锁集合只增不减，不应因规则调整回收 |
| 皮肤 | 星夜依赖省电估算；极光依赖单次 2 小时；樱雨/翡翠依赖连续 14/60 天；熔岩依赖满级再储备 2000 成长值，即 8000 | 成长规则直接影响熔岩的未来获取速度；其他皮肤并非待收容量或有效期直接决定。现有解锁须保留 |
| 备份 | JSON 保存已收集 `gp`、会话、养成及成就状态；不保存待收球、各球到期时间或分钟零头。历史聚合从恢复明细重建 | 不能宣称导出/恢复后待收库存无损延续；系统整应用迁移与该 JSON 格式不是同一机制 |

## 三种数值方案

以下数值为供后续决策的明确候选，不是本轮已实现或已验证的规则；对留存、满意度及成长速度的真实影响均未知。

| 方案 | 明确数值与行为 | 用户影响 | 存量与实现影响 |
|---|---|---|---|
| A 保留现行规则（推荐本轮） | 容量 200；有效期 72 小时；临期 12 小时；主动收取 | 保持已发布预期；长会话或忘记收取仍可能损失能量 | 无数值迁移，不重算历史成长；通过准确解释区分待收与已收集 |
| B 扩大容量 | 候选容量 600；其他规则不变 | 在无额外奖励的情况下，未收取空间由约 200 分钟增至 600 分钟；减少长时间听剧满仓损失，但仍会过期 | 原有球与到期时间原样保留，只扩大新增容量；不补发已丢能量。需同步能量条容量展示，验证剩余空间与截断边界；会加快部分用户成长，幅度未知 |
| C 延长有效期 | 容量仍为 200；候选有效期 168 小时（7 天）；临期仍为 12 小时；主动收取 | 给偶尔回访用户更长收取窗口；满仓问题不解决，持续听剧仍可能被截断 | 推荐仅新生成球采用新有效期，旧球保留原到期时刻，避免凭空延长或复活过期球；若产品选择统一延期，必须另定版本化迁移、一次性执行和异常回退规则 |

B 与 C 不能未经评估直接叠加。降低容量或缩短有效期会让存量用户损失已形成预期的收益，不作为推荐候选。任何变更均不得回退已收集成长值、回收已解锁形态/成就/皮肤，或用历史时长伪造过期奖励补偿。

## 自动收取的独立边界

全量方案 F09 还包含自动收取评估。自动收取将改变“听剧产生待收球 → 主动收取 → 成长”的交互契约：若生成时立即收取，200 容量与 72 小时过期几乎失去作用；若仅进入统计页时收取，则仍不能解决长会话先满仓和离开超过有效期的问题。它不是单纯扩容或延长有效期的等价替换。

本轮不启用自动收取。未来若明确采用，需先定义触发时机、旧待收球处理、到期边界、重复结算防护、离线/进程重启行为，以及成长动画和备份含义；不要通过“打开页面顺便自动收取”静默改变契约。

## 推荐与后续反馈

本轮选 A。源码事实已经足够证明应纠正“每日上限”表述，但没有真实反馈证据支持直接决定 600 或 7 天更合适。先观察用户是否主要遇到长会话满仓、忘记收取、对过期不理解，还是认为主动收取本身多余，再分别评估 B、C 或自动收取。无需为此新增联网埋点；用户主动提供的体验描述及经同意的本地复现即可作为后续输入。
