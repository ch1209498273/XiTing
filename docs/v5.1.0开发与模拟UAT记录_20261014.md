日期：2026-10-14。版本：5.1.0 / code89。范围：用户已授权的开发与模拟器 UAT。候选未发布。模拟验收后已追加实体手机覆盖升级与哔哩哔哩验收，见下方追加记录。

## 交付内容

本轮围绕“在播放器旁设置、黑幕内调整、到期后知道结果”实施，沿用 v4 首页、三个页签、启动/停止按钮和返回手势。

- 黑幕内增加定时入口与暗色面板，显示播放器名称、图标；支持15/30/60分钟、1–600分钟步进自定义、有效进度下的片尾定时，以及返回画面/暂停并保留黑幕两种结束动作。编辑期间不会被5秒重锁打断。
- 显式选择的媒体目标暂时 inactive 时保留；销毁后明确失效，不自动切到另一会话；撤销媒体权限后不使用缓存目标。
- 首页与黑幕设置经服务确认才显示成功。拒绝时保留原定时与输入；处理期间销毁、媒体身份改变、请求超时分别校验。
- 按应用保存已受理的时长与结束动作，不保存媒体标题/token。新偏好支持备份，损坏数据与旧备份保持兼容。
- 两项首次成功确认后收起首页引导，“关于”仍能重新体验；到期提示读取最终暂停结果。

新增实现主要为 `PlaybackSelection.kt`、`TimerRequest.kt`、`CurtainTimerPanel.kt`、`PlayerTimerDefaults.kt`，配合现有服务、弹窗、黑幕和首次使用流程。没有新增依赖或权限。

## 验收方法与边界

使用 Android 框架真实 MediaSession 和应用真实窗口、服务、按钮及悬浮球；会话由测试构造，两个会话属于同一测试应用，不能写成“两款真实播放器”。一分钟流程实际启动服务、点击球开启黑幕、唤醒并打开面板、设置1分钟暂停、等待到期、检查原目标暂停及另一个会话未收到暂停、点击返回并停止。

测试夹具仅允许模拟器执行，结束恢复备份和偏好。当前设备只有 API26/33/35 模拟器；此前手机与哔哩哔哩记录不计作本轮通过证据。

## 已发现并修正的问题

1. 原显式目标查询会回退其他会话：增加明确选择生命周期与失效状态。
2. UI提交即关闭：改为服务受理回执，拒绝保留输入。
3. 黑幕没有定时设置入口：增加原窗口内面板，暂停编辑时重锁。
4. 英文预设按钮下沿裁切：关闭行基线对齐并缩短分钟单位，实际点击/可见区域复验。
5. API26 已释放控制器仍返回缓存 PLAYING：提交前注册独立销毁观察，服务延后一轮校验，定时目标持续观察生命周期。
6. 上述校验曾误拒绝不依赖播放器的固定返回：按动作区分依赖，失效可选控制器不重建、不保存偏好。
7. 测试工具在API26将 shell 引号写入媒体权限配置：去掉引号并恢复正确配置。短时夹具在繁忙模拟器中可能提前到期，改为10秒并断言销毁/撤权发生在到期前；等待最终结果落定，保留原失败日志。
8. API35直接写权限配置可能被系统纠正，夹具改为通过系统通知授权/撤权命令管理本应用授权；只在API26使用配置写入，保留其他应用的授权。
