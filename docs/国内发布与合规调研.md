# 国内发布渠道与合规调研（2026-10-02）

> 调查方法：酷安开发者平台（developer.coolapk.com）实地探测 + 2024 年个人开发者上架亲测文章（CSDN）+ 行业备案政策文章交叉验证。官方文档在登录墙内，标注「待确认」的项以开发者后台实际字段为准。

## 一、酷安完整发布流程（截至 2026 年现状）

### 背景（已核实的时间线）
- **2019-05-22**：酷安清理过一次所有非实名认证开发者的应用（知乎 17.7 万浏览的讨论即此事）。实名认证自此是硬门槛。
- **2021 年**：酷安是「个人开发者天堂」，无软著、无隐私政策要求；特有的「空签名包重签」验证机制。
- **2023-08 起**：工信部 App 备案政策落地，各大商店陆续强制；2024 年初的个人开发者亲测文章确认：**上架商店基本需要 ①软著 ②App 备案**（不联网应用存在豁免路径但执行不一刀切）。
- **2024 年亲测结论**：酷安仍接受个人开发者，审核「相对慢一些、中规中矩」；OPPO/vivo 不开放个人开发者；华为支持个人但一律要备案。

### 完整流程（12 步）

**阶段 A：准备（发布前一次性）**
1. **注册账号**：在酷安 App 内注册（官网提示「请使用酷安 APP 进行注册」，网页端不开放注册）。
2. **开发者实名认证**：登录 developer.coolapk.com → 提交身份证 + 人脸识别。未实名无法上传应用。
3. **准备隐私政策**：需要一个可公开访问的 URL。我们的方案：GitHub 仓库里的 PRIVACY.md（纯离线声明：不收集任何数据、无网络权限、数据仅存本机）。
4. **正式签名 release 包**（见 A1）：酷安签名验证基于你的 release keystore。

**阶段 B：签名验证（酷安特有）**
5. 在开发者后台创建应用，酷安会下发一个**空签名验证包**（CoolApkDevVerify 机制）。
6. 用你自己的 keystore 给这个空包重签（jarsigner 命令），回传上传——酷安以此确认后续上传的 APK 签名一致、防止包被冒认。

**阶段 C：提交材料**
7. APK（release 签名版）
8. 图标 512×512 + 截图 3~5 张（小红书 8 张卡可直接裁用）
9. 简介（一句话 + 详细介绍）、分类（工具/影音）、关键词
10. 隐私政策链接 + 版本更新说明
11. **App 备案号字段**：待确认——酷安后台是否强制填写。政策上不联网 App 有豁免讨论空间（应用宝明确支持「不联网应用 + 软著」豁免备案上架；酷安执行口径需在提交时问客服或在后台试填）。若必须备案：个人主体备案不需要软著，但需要**一台云服务器**（阿里云/腾讯云购买后由云商出备案服务码，提交身份证，工信部审核约 1 周，免费）。

**阶段 D：审核与发布**
12. 人工审核，通常 1~3 个工作日（有初筛 + 复审；「相对慢」是社区共识）。通过即上架，后续更新走同后台，每次更新重新审核。

### 酷安之外的个人开发者渠道（2024 亲测排序）
| 渠道 | 个人开发者 | 备案 | 备注 |
|---|---|---|---|
| 应用宝 | ✅ | 单机 App + 软著可豁免备案 | 审核相对宽松，明确的「不联网」路径——**和我们最匹配的大厂渠道** |
| 华为应用市场 | ✅ | 一律要备案 | 审核最严格，量最大 |
| 360 商店 | ✅ | 要 | 必须 APK 签名加固，流程繁琐 |
| 应用汇 | ✅ | 要 | 存量小 |
| 酷安 | ✅ | 待确认（大概率要） | 人群最匹配 |
| OPPO/vivo | ❌ 不开放 | — | 需要》，个人无法上架 |
| 蒲公英/pgyer | ✅（实名） | — | 内测分发平台，非商店；适合给小红书挂国内直链 |
| 吾爱破解原创区 | ✅ | — | 论坛发帖，无商店规则，流量大 |

## 二、法律合规性审查

### 2.1 必办事项（风险：高 → 不办不能上架）
| 事项 | 现状 | 动作 |
|---|---|---|
| 工信部 App 备案 | 未办 | 政策依据《关于开展移动互联网应用程序备案工作的通知》(2023-07)。纯离线应用在政策上有讨论空间（「不从事互联网信息服务」），但商店执行普遍一刀切。路径：买最低配云服务器拿备案服务码 → 以个人主体提交 → 约 1 周。费用：服务器 ~50-100 元/年（新人价）+ 备案免费 |
| 隐私政策 | 无公开版 | 写 PRIVACY.md：声明不收集、不传输任何数据，无 INTERNET 权限；列出悬浮窗/通知/电池优化/自启动各权限的用途。挂 GitHub，给商店链接 |
| 正式签名 | 未配（一直 debug 包） | 生成 release keystore，永久保管（换签名 = 用户必须卸载重装 + ANDROID_ID 变化破坏备份恢复逻辑） |

### 2.2 权限合规（PIPL《个人信息保护法》+《常见类型App必要个人信息范围规定》）
- 我们收集 **零个人信息**、无网络权限 → 在 PIPL 下处于最强合规位置（工具类 App 最小必要：无）。
- 权限逐项声明用途（写进隐私政策）：
  - `SYSTEM_ALERT_WINDOW`：悬浮球与全屏黑幕（核心功能）
  - `POST_NOTIFICATIONS`：常驻通知显示运行状态与快捷控制
  - `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`：防止息屏服务被系统杀掉
  - `RECEIVE_BOOT_COMPLETED`：开机恢复用户主动开启的助手
  - `WAKE_LOCK`：黑幕期间维持会话计时
  - （若做白名单自动息屏）`PACKAGE_USAGE_STATS`：敏感权限，需在隐私政策中专门说明且商店审核会问用途

### 2.3 知识产权
- **自己的 LICENSE**：现有自拟许可证（禁止商用/禁止去除溯源水印）合法有效，作为版权人不受约束。
- **图标**：用户提供的 AI 生成图。中国司法实践（北京互联网法院 2023 判例）对有人类智力投入的 AI 图片认可著作权；作 App 图标风险极低。
- **应用名「息屏听剧」**：描述性词汇，商标风险低；若日后做大可花 ~300 元/类 注册 45 类中的第 9 类（软件）。
- **代码**：纯 Android SDK，无第三方依赖 → 无开源传染性义务。

### 2.4 平台条款
- 对视频 App 仅做「显示层覆盖 + 触摸拦截」，不修改、不自动化、不绕过 DRM、不屏蔽其广告 → 不违反其服务条款；LICENSE 已声明与视频平台无关联。
- 宣传物料检查（广告法）：无「最/第一/国家级」极限词 ✓；「省电 305 mAh」标注了估算口径 ✓；「100% 本机」为可验证事实 ✓。

### 2.5 风险点与低风险项
| 风险点 | 等级 | 说明 |
|---|---|---|
| 未备案分发 | 中 | 商店强制；直接 APK 分发（GitHub/蒲公英）执法上主要针对平台，但合规起见建议办 |
| 溯源水印声明 | 低 | LICENSE 中的水印台账是自保护机制，注意隐私政策中提一句「应用包含构建标识（非设备信息）」 |
| 域名/服务器 | 低 | 若办备案则顺手做一个静态官网（隐私政策+介绍），一举两得 |

## 三、广告的考虑与可能性

### 现状：技术上「加不了」
应用**没有 INTERNET 权限**，广告 SDK（穿山甲/优量汇等）全部需要联网加载 → 当前架构下广告根本无法运行。这是架构级选择，不是配置。

### 若要加广告，代价清单
1. 加 `INTERNET` 权限 →「完全离线 · 不收集数据」核心卖点崩塌，README/关于页/小红书物料全部重写
2. 接广告 SDK → SDK 会收集设备信息（IMEI/OAID/位置等），必须重写隐私政策、维护 SDK 合规清单；**广告 SDK 是工信部「违规收集个人信息」通报的头号来源**
3. App 备案从可讨论变为硬性必须
4. 《互联网广告管理办法》(2023-05) 要求：广告必须标明「广告」、弹窗广告须一键关闭、不得诱导点击，违规最高罚款
5. 酷安用户对广告极其敏感，社区口碑反噬风险大
6. 工具类 App 的广告收益极低（打开频次低、时长短），预估月收入个位数到几十元人民币

### 替代方案（推荐）
- **赞赏入口**：关于页加「请作者喝杯咖啡」→ 微信赞赏码图片 / 爱发电（afdian.net）/ GitHub Sponsors 链接（浏览器打开，App 本体仍无网络权限）
- 亦符合现有 LICENSE 精神（禁止他人捆绑广告，作者自己也不必加）
- **结论：现阶段不加广告。** 若未来想做，独立出「免费版/赞助版」两个变体，别污染主版本。

## 四、遗留技术问题的答案（备忘）

### 耳机拔出自动暂停——厂商做了吗？
- **做了，但只做一半**：有线耳机拔出时，Android 系统广播 `AUDIO_BECOMING_NOISY`，爱奇艺/B站等 App 会自动暂停——这是系统级行为，厂商不需要额外做。
- **没人做的一半**：我们的黑幕不知道「剧已暂停」。用户拔耳机后面对的是一块还在「息屏听剧中」的黑屏，体验断裂。
- 所以该做的不是「暂停」（App 自己会），而是**黑幕联动**：监听音频设备变化（ wired `BECOMING_NOISY` + 蓝牙 `AudioDeviceCallback` 断连），自动退出黑幕回亮屏，让用户直接看到已暂停的视频界面。蓝牙断连系统没有标准广播，是真正的差异化点。

### 省电估算用真实电池数据校准——技术上怎么做？
1. **采样**：黑幕会话期间每 30-60 秒读一次 `BatteryManager.BATTERY_PROPERTY_CURRENT_NOW`（µA，电池瞬时电流）。
2. **积分**：µA × 时间间隔累加 → 本会话实际耗电 µAh。
3. **排除脏数据**：充电中（plugged != 0）、电量 <15% 或 >95% 时丢弃样本（电流读数失真）；不同机型电流符号方向不同，取绝对值 + 滑动窗口滤毛刺。
4. **校准模型**：积累 ≥30 分钟有效黑屏样本后，用「实测黑屏态均流」替换省电公式里 OLED 屏功耗常数中的屏幕项；更进一步的「5 分钟校准向导」：引导用户先亮屏看视频 5 分钟采样、再黑屏 5 分钟采样，差值即本机真实省电速率。
5. **UI**：统计明细区分「模型估算 / 已实测校准（N 分钟样本）」，避免过度承诺。

### A1（正式签名）是干嘛的？
- 现在发的 APK 一直是 **debug 签名**（构建工具自动用 IDE 调试密钥签的）。
- 正式分发需要：自己生成一个 release 密钥库（keystore）→ 配进 gradle → 出 release 包（顺带 R8 压缩减包体）。
- 为什么必须：① 签名就是应用的身份——**换签名用户无法覆盖安装，必须卸载重装**；② 我们的备份恢复依赖 ANDROID_ID，而 Android 8+ 的 ANDROID_ID 与签名绑定，debug→release 切换会让老用户数据恢复逻辑断裂；③ 酷安的签名验证机制基于你的 release keystore。
- 所以：keystore 生成一次、密码记牢、永久保管——这是所有对外分发的前提。
