# 息屏听剧：UI 与功能升级全量方案

编制：2026-10-12；复核：2026-10-13。状态：全量范围与统一排序方案；各项实现、测试和发布状态须另按证据核对，本文不作完成声明。

## 1. 基线与目标

用户选择 B「清爽工具感」，要求覆盖全量 UI，并与此前功能优化统一排序。

原方案以 v4.3.0 / code84 为起点。2026-10-13 复核时，本地 `app/build.gradle.kts` 已标为候选 v4.4.0 / code86，并存在本轮开发及测试文件。版本配置不代表构建、UAT或发布已经通过；本文用于统一需求与排序，不将已有功能、候选改动和已发布结果混为一谈。

已实现并保留：睡前定时结束动作、十秒黑幕演示、五阶互动预览、金色勋章与解锁庆祝、图标换肤、深色模式、八语言、本地备份、小组件、分享海报和月报年报。它们进入视觉整合与必要补强，不重复作为新功能开发。

目标：用户一眼理解运行状态，一步找到主要操作；听剧数据易读，精灵与成就有清晰反馈；日间、夜间、不同语言保持一致。预计效果是设计假设，需实际使用验证，不预先承诺留存、耗电或操作效率提升。

继续使用本地、轻量、无 INTERNET 权限的定位。首轮保留原生 Android View/XML 与现有绘制体系，不因 UI 改造引入框架迁移、在线字体或大型素材包。

## 2. 设计规范

| 项目 | 方案 |
|---|---|
| 风格 | 浅灰页面、白色表面、绿色主操作；减少装饰渐变与多色圆底，依靠间距和字体建立层级 |
| 品牌 | 延续现有绿色；金色仅用于成就与奖励，不与主操作争夺注意力 |
| 深色 | 同步提供深灰页面与分层表面；黑幕沿用独立纯黑体系，不把浅色页面规范套入黑幕 |
| 字体 | 系统字体；建议页面标题 22–24sp、区块标题 17–18sp、正文 14–16sp、辅助信息 12–13sp；关键状态不依赖小字 |
| 间距 | 4/8/12/16/24dp 分级；页面横向留白建议 20dp，小屏可收至 16dp |
| 形状 | 卡片建议 16dp 圆角，按钮 12dp，状态标签胶囊；以浅描边或表面色分层，阴影克制 |
| 控件 | 统一主按钮、次按钮、危险动作、列表项、开关、状态标签、分段选择与空状态 |
| 可读性 | 正常、选中、禁用、错误均有文字或图标区分；先验证对比度再确定色值 |
| 触控 | 主要交互目标建议不小于 48dp；视觉尺寸可小于触控区域；图标按钮提供语义标签 |
| 动效 | 常规状态变化建议 150–250ms；庆祝使用已有有限动画，隐藏或失焦停止，遵守系统动画设置 |
| 适配 | 支持窄屏、大字体、横屏和长译文；内容可换行，避免通过持续缩小字体解决拥挤 |

上述尺寸为设计起点，需以原生渲染结果调整，并非已经验证的像素定稿。

## 3. 导航与页面全量方案

### 3.1 应用框架

首轮保留「首页 / 统计 / 设置」三个底部入口，避免同时改变导航结构和使用习惯。页面标题随页签变化；运行状态在首页主区域表达，减少标题与状态标签挤占同一行。底部导航统一图标笔画、选中底色与标签状态。

精灵在统计页形成完整成长区，图鉴和成就保留二级入口。首轮不新增第四个页签；若真实使用显示成长区过长、访问频繁，再评估独立入口。

### 3.2 首页：先操作，再解释

从上到下：

1. 标题与简短说明。
2. 助手主卡：未启动、准备就绪、正在黑幕、权限阻断等状态；主要按钮使用与真实动作一致的文字。「启动悬浮球」与「进入黑幕」必须分清，已运行时「停止助手」作为次操作。
3. 睡前定时卡：未设置时展示入口；设置后展示剩余时长、结束动作与目标播放器，并提供调整和取消。
4. 播放器支持卡：按实际可读信息展示来源、暂停/跳转支持状态；读取不到时明确原因，不用错误的空白剧名代替说明。媒体读取仍遵循可选授权。
5. 条件式问题提示：只有关键权限缺失或存在待处理项时展开。后台保活作为建议入口，不把建议状态等同于核心功能无法使用。
6. 首次体验与帮助：新用户显著展示演示入口，老用户收为次级入口，仍可再次访问。

不把精灵搬到首页占据主操作位置，不显示无法从现有权限可靠判断的播放器状态。

### 3.3 统计页：先数据，再成长

推荐顺序：时长摘要 → 近七天趋势 → 本周小结与分享 → 省电估算 → 精灵成长与成就 → 最近记录。

- 摘要沿用今日、本周、累计数据，不改变统计口径；用一个主要数字和次级指标减少三个等权小卡的拥挤。
- 图表使用稳定单位、明确日期，提供选中日期的数值；无数据时给真实空状态，不填入示例柱。
- 本周小结保留周边界与同比口径，分享作为次操作。
- 省电卡清楚标注「通用模型估算」「基于本机样本估算」「暂不可用」；样本数量与场景限制可展开查看，不以采样次数冒充统计学置信度。
- 成长区包含当前精灵、成长值、距下一阶剩余值、待收能量与收取按钮；区分当前佩戴形态和实际成长阶段。
- 成就入口显示解锁数和真实记录；历史解锁日期缺失时标为未知。
- 最近记录突出日期、时长和模式；保留现有分页，首轮不增加复杂搜索或新统计维度。

移动精灵位置时核对所有成长区跳转，避免沿用旧坐标。未解锁成就点击后保留列表并展示条件，不强制跳到成长区；仅明确的「查看成长」入口才滚动到真实成长区。

### 3.4 图鉴与精灵预览

顶部是当前预览形态，中部显示名称、状态与门槛，下方为形态选择、配色和动作入口。

明确区分「正在预览」「已经解锁」「当前佩戴」；未解锁仍可互动预览，佩戴按钮显示条件。切换预览不写成长或佩戴状态。退出时无隐式解锁或数据修改。

首轮复用现有五阶造型，统一周边布局，不重画整套角色。进化转场作为后续独立项。

### 3.5 成就列表与详情

保留四项成就与金色勋章。列表统一为徽章、标题、条件、进度和状态；已解锁可查看详情与重播，未解锁进入条件说明，不再只把用户送回精灵区域。

进度使用已有对应指标：单次最长时长、连续天数、累计次数、成长值。连续成就同时说明当前连续与历史最佳，解锁仍以既定历史最佳规则为准。

为新解锁记录时间与稳定顺序，修正摘要「最新」含义。旧记录无日期不得编造；升级时补判达成的记录也应区分「首次记录于」和真实历史达成日期。新增字段必须随备份导入导出兼容。

### 3.6 设置与关于

按以下分组整理现有功能：

- 播放与黑幕：进入方式、媒体控制、夜钟与电量、耳机断连动作、使用建议。
- 外观：悬浮球样式、桌面图标、语言；先沿用系统深色跟随，手动主题选择不列首轮必做。
- 权限与后台：悬浮窗、通知、通知使用权、后台保活说明及实际可查询状态。
- 数据：导出、恢复、备份说明与可验证的最近备份状态。
- 关于与帮助：版本、下载入口、使用说明、隐私、已有诊断入口。

开关直接表示当前状态；需要系统权限的选项说明依赖，跳转返回后刷新真实结果。实验性字幕入口与说明依据现有决策处理，不借设置重排恢复已放弃功能。

关于页、应用内隐私文字、PRIVACY.md、README 按实际权限、媒体数据读取、实验性无障碍与备份行为统一说明。

### 3.7 定时面板

集中呈现预设、自定义时长、结束动作和目标播放器，减少来回跳转多个弹窗。提交前展示完整结果，如「30 分钟后，向某播放器请求暂停，保持黑幕」。

未满足条件时提示具体依赖；验证失败保留输入和原定时。编辑当前定时与修改下次默认值必须分清。重新选择目标需要明确应用，不能静默改发给另一个播放器。

先修正位置与倍速计算，再实现面板；中途暂停、拖动、变速后的片尾策略需在实施定时增强前明确设计。

### 3.8 黑幕与唤醒控制

锁定态保持纯黑或用户选定的暗色信息，不增加常驻装饰与提醒。

唤醒态按「播放器与标题 → 媒体控制 → 定时状态与调整 → 返回视频」建立层级。五个媒体按钮保持足够间距；不支持的能力按契约隐藏或解释，不出现可点击但无效的控制。

定时取消/延长只在用户主动唤醒并操作时执行；需处理五秒重锁与面板交互，面板不得意外亮屏或失去可恢复出口。快捷调整依赖核心定时逻辑验收后再进入。

### 3.9 悬浮球、通知与桌面小组件

- 悬浮球：延续文字/精灵两种选择与既有手势，保持固定窗口尺寸和足够触控面积；本轮不顺带改变退出手势。
- 通知：统一运行与定时描述，保留既有操作；遵循系统通知布局，不模拟 App 内复杂卡片。
- 三种小组件：同一数据口径与图标语言，按尺寸逐级显示主操作、关键时长与成长反馈；事件驱动刷新保持现状。
- 已发布桌面图标资源保留，本轮先统一选择页，不再做一套新图标。

### 3.10 分享、备份与通用反馈

分享预览明确展示内容范围、3:4/1:1 比例、分享与保存操作。海报沿用现有角色与布局能力，统一标题和数据层级，不强行套用 App 白色卡片。未验证的省电结果不得以确定值输出到海报。

备份恢复先展示来源、日期、可读数据摘要与覆盖影响；无效文件停留在原流程，导出失败可重试，历史未知字段不伪造。是否增加恢复前快照作为实现阶段的独立方案评估，不默认为已实现。

所有页面覆盖空、加载、成功、失败、无权限、不可用、选中和禁用状态；持久问题用页内反馈，短暂确认用轻提示，覆盖数据等重要动作单独确认。

## 6. 验收标准

- 首页：未授权、未启动、已启动、黑幕中、无媒体会话等状态均有明确主操作；展示与实际服务状态一致。
- 播控：播放/暂停、过期位置、片头片尾、连点、多个会话与权限撤销时，不产生跳转越界或错误目标选择。
- 定时：普通时长、不同倍速、当前已暂停、目标失效、第三方不响应、编辑/取消逐项验证；请求暂停不被表述为已经确认暂停，不意外恢复亮度。
- 统计：新用户零记录、长时长、大数值、缺失样本和不支持计数器时可读；统计范围与周边界不随重排变化。
- 成长与成就：佩戴/成长/预览分离；新旧备份恢复完整；未知日期如实展示；新解锁与重播不会重复增加奖励。
- 视觉：所有关键页面覆盖浅色和深色；八语言检查完整性，对长译文、窄屏和大字体做定向渲染检查；按钮标签不重叠或裁切。
- 动效：页面不可见、失焦、关闭动画时不持续重绘；沿用已有金色勋章验收，不因布局整合破坏生命周期。
- 黑幕：原有两段解锁、自动重锁、返回恢复、来电与耳机联动必须回归；不以静态截图证明后台或亮度行为。
- 桌面：三种小组件实际尺寸可用；悬浮球固定窗口尺寸，语言切换不变形；通知操作真实生效。
- 工程：运行相称单测、构建、完整 lint 与翻译检查；记录候选 APK 大小及相对 v4.3.0 的增量；不为静态可逆布局逐项编写复述实现的测试。
- 设备：模拟器验证布局与状态；主力实体设备验证黑幕、后台、媒体与系统联动。记录机型、系统和播放器版本，不能推广为全机型支持。

## 7. 范围与实现边界

不纳入：OCR 字幕、本地播放器、播放中断提醒、账号、排行榜、服务器推送；不将已放弃路线包装成 UI 升级依赖。

本轮不修改四项成就门槛、能量上限或过期规则；F09 只列后续评估。对已发布徽章与图标优先复用，不因新视觉重复建设。

布局入口为 `activity_main.xml`、`page_home.xml`、`page_stats.xml`、`page_settings.xml`；颜色复用语义 token 并成对维护浅深色。定时、预览与详情保持独立实现入口，避免把新业务持续堆进 MainActivity；只做改版所需的局部解耦，不另开全项目重构。

关键依赖：播放位置与目标选择是共享基础；成就记录涉及持久化与备份；统计页重排影响滚动定位；黑幕定时面板影响重锁与亮度生命周期。这些需在实施计划中单列，不能按纯配色改动估算。

## 8. 依据与限制

当前依据为源码静态检查、已有候选验收、发布记录与用户选择；未开展新一轮用户研究、实机耗电实验或全量兼容性验证。

Android 官方定义：BATTERY_PROPERTY_CHARGE_COUNTER 为 µAh，BATTERY_PROPERTY_ENERGY_COUNTER 为 nWh。当前最终除以1000转mAh不必然错误，需要修正的是混用单位、异常阈值、功耗解释与证据展示，不在未验证前宣称现有结果整体偏大或偏小。
