# 内容找回最小验证

用户已同意先证明找回价值，并要求先在模拟器开发，不等待实体机。本轮允许安装官方视频App、只读检查媒体信息与分享内容、编写最小隔离验证工具；不直接开发原记录库。

## 问题与成功标准

- 正常播放时，能否获得与画面一致的内容名称、稳定身份和进度？每项独立记录。
- 黑幕、换集、切App后，是否仍能分辨旧内容与新内容？不猜未知信息。
- 原App分享能否交给外部App有效链接与标题？取消、复制链接和系统分享分别记录，不混为一种能力。
- 记录链接再打开，是否返回同一视频？返回首页/搜索页不能算找到内容；确有可验证位置时才评估进度恢复。

## 工作顺序

1. 启动现有模拟器，检查ABI/ARM转译；从官网下载安装包，记录下载来源、实际版本与安装结果。
2. 对可运行App使用未登录公开内容；不购买、不注册、不绕过安全验证。进入视频→读取媒体能力→黑幕前后对照。
3. 检查原分享入口；必要时用仅存在于测试构建的分享接收器捕获用户实际交出的字段，不增加发布版入口。
4. 使用实际收到的链接返回；记录是否同视频，区分浏览器网页/原App/只打开首页。
5. 有至少一条真实App闭环成立才设计“最近听过＋标记＋保留/删除”的最小产品。无闭环则给出具体限制，不用自动时段列表冒充内容找回。

## 当前静态结论

- NowPlaying当前提供title、App、position/duration和canSeek，没有保存可返回的内容链接。
- controlsReliable=false时主动舍弃标题和seek；不能通过存下可能陈旧的字段绕过可信性检查。
- EpisodeTimerTarget的title+duration回退仅为短期片尾观察，不能当长期内容唯一身份。
- 旧listen session只有时段，无法恢复历史视频。现有来源识别/暂停通过不等于内容找回通过。

## 验证范围和记录

目标：哔哩哔哩普通视频、抖音短视频、爱奇艺公开可播内容。模拟器若不支持实际包架构，记录安装错误并优先寻找已有兼容镜像；不把网页视频当Android App已通过。可独立验证的链接解析和本机操作可继续开发，但不扩大兼容结论。

输出：`docs/uat-content-return-20261016/`中的环境、安装结果和内容找回矩阵。第三方标题/链接只采用公开测试样本；不归档个人账号或私人观看记录。
